# Monthly content variety automation — design spec

**Date:** 2026-07-29
**Status:** Approved, pending implementation plan

## Problem

Everest Motoring's July 2026 plan had 12 static posts across 6 templates plus rotating
finance/comparison/seasonal-local angles, a carousel, and 2 cinematic lifestyle videos.
August's plan, generated by clicking "Generate Marketing Plan" in the app, had none of
that — just the same 4 templates repeated identically, no videos.

Root cause (see `superpowers:systematic-debugging` investigation this session): July's
variety was never a reusable feature. It was hand-built via one-off scripts
(`scripts/build-client-review.mjs`, `scripts/revise-july-angles.mjs`, hardcoded to July's
workspace ID/token/dates) plus manually-run video scripts
(`scripts/seedance-family.mjs`, `scripts/seedance-reel.mjs`, `scripts/append-outro.mjs`).
None of that touches the actual production path.

The button's real code path is `POST /api/workspaces/campaign/generate`
([route.ts](../../../src/app/api/workspaces/campaign/generate/route.ts)), which runs a
fixed, deterministic 4-pillar weekly rotation (`showcase`/`lifestyle`/`maintenance`/
`seasonal`, Mon/Wed/Fri/Sat) with no angle variety and no video step at all. A separate,
richer generator (`src/lib/ai/campaignGenerator.ts`, six styles + psychology notes +
pillar pools) exists but is wired only to a disconnected preview button on the
`intelligence` dashboard page — it never inserts posts and was not the source of July's
output either.

## Goal

Make `/api/workspaces/campaign/generate` itself produce recurring variety, every month,
for any car-dealer workspace on ember-social — not just Everest, and not requiring anyone
to remember to run a one-off script.

## Out of scope

- **Carousel** as a selectable style. `src/lib/templates/carousel.ts` is explicitly a
  prototype — the `posts` schema/scheduler assumes one image per post, so a true
  swipeable Instagram carousel needs a separate multi-image schema + composer + IG
  carousel-upload change. Decided to skip for this cycle.
- Changes to the disconnected `campaignGenerator.ts` / `/api/ai/campaign` preview path —
  left as-is.
- Any non-dealership (service/hospitality/education/creator) archetype support. The 4
  existing templates are already vehicle-specific (`VehicleInput` required); this design
  stays within that scope.

## Part 1 — Angle rotation (finance / comparison / seasonal-local)

Of the 16 monthly static-post slots (4/week × 4 weeks), **2 become rotation seats**
instead of being fixed. Candidates for those 2 seats, per workspace, per month: the
angle **not used in the last ~2 completed months** for that workspace, drawn from:

- `finance` — affordability/monthly-installment hook (mirrors July's Suzuki Swift
  "±R4,400/month" post, `studio`-style render with a finance footnote)
- `comparison` — two vehicles side-by-side, "which one is you?" (mirrors July's Tucson
  vs. Kiger post, `multi_car`-style 2-up render)
- `seasonal_local` — calendar/season-tied local hook (mirrors July's "long weekend
  ahead" T-Roc post, `lifestyle_hero`-style render)
- `seasonal` — the existing default (today's only Saturday option), stays in the pool so
  it can still win a seat when the other three were all used recently

**Selection mechanism:** query that workspace's `posts.pillar` values from the last ~2
months (`campaign_batches` + `posts` already carry this history — no new tracking table
needed). Rank the 4 rotation candidates by recency of last use (never-used treated as
oldest); the 2 seats go to the 2 least-recently-used. This is self-correcting: if a month
is skipped, generated late, or done manually, the next automated run just looks at
whatever the actual history shows.

**New render functions**, added alongside `showcase.ts`/`lifestyle.ts`/etc. in
`src/lib/templates/`: `finance.ts`, `comparison.ts`, `seasonal-local.ts`. Same
`(car, opts) => Promise<RenderResult>` shape the existing 4 already use, so they drop
into `PILLARS` / the rotation-seat selection in `route.ts` without changing its overall
structure.

**Which 2 of the 16 slots are rotation seats:** the Saturday slot (today's `seasonal`)
every week, plus the week-2 Wednesday `lifestyle` slot — `lifestyle_hero` was already
July's most-flexible template, and `seasonal_local`/`comparison` are natural swap-ins
there. Both seats are decided independently (each looks at the 4-candidate pool and
picks whichever wasn't used recently), so the same angle could theoretically win both
seats in one month if it hasn't run in ~2 months and the others have — acceptable, since
it still means the seat isn't repeating the *previous* month's choice.

## Part 2 — Video automation (3 videos/month, non-repeating concepts)

### Constraint that shapes the design

`scripts/seedance-family.mjs` polls kie.ai for **up to 12 minutes**
([seedance-family.mjs:90](../../../scripts/seedance-family.mjs#L90)). Vercel functions
cap at 300–800s even on Pro/Fluid Compute. Three renders cannot complete inside the
single request that handles "Generate Marketing Plan" — this has to be an async job
processed across multiple invocations, not one big synchronous call.

### Concept bank

The 6 concepts already documented in the July plan doc (§4 "Policy for months after
July"): `born_for_the_bundu`, `first_car_first_freedom`, `work_hard_play_harder`,
`date_night`, `sunday_drive`, `two_minute_tips`.

### New `posts` columns

Mirrors the existing `image_status` pattern
([009_posts_image_prompt.sql](../../../supabase/migrations/009_posts_image_prompt.sql)):

```sql
alter table public.posts
  add column if not exists video_status text
    check (video_status in ('pending','generating','rendering','compositing','ready','failed')),
  add column if not exists video_concept text,
  add column if not exists video_task_id text,
  add column if not exists video_prompt text;
```

`media_urls` is reused for the final video URL once ready — no new column needed there;
`ClientView.tsx` ([ClientView.tsx:259](../../../src/app/plan/[token]/ClientView.tsx#L259))
already renders `<video>` for it.

### Flow

1. **At plan-generation time** (`route.ts`): query each workspace's `video_concept`
   history over the last ~N months, pick **3 concepts not used recently**, insert 3
   `posts` rows with `video_status='pending'`, `video_concept` set, scheduled at
   weeks 1/2/3 (mirrors July's week-2/week-4 video slots, extended to 3).
2. **New cron** `/api/cron/generate-videos` (`maxDuration=300`, runs every ~10 min,
   registered in `vercel.json` alongside the existing `publish-scheduled` and
   `news-monthly` crons). Each tick, picks up **one** job not in a terminal state and
   advances it one step:
   - `pending` → generate the Seedance prompt for that concept + vehicle(s), submit to
     kie.ai (`createTask`, same call `seedance-family.mjs` makes), store
     `video_task_id`, set `video_status='generating'`
   - `generating`/`rendering` → poll `recordInfo` for that `video_task_id`; on
     `success`, download the result, set `video_status='compositing'`
   - `compositing` → append the branded outro via `ffmpeg-static` (same approach as
     `scripts/append-outro.mjs`, ported to be route-callable; writes to Vercel's `/tmp`
     scratch space), upload to Supabase storage, set `media_urls`, `video_status='ready'`
   - any step throws → `video_status='failed'` with the error recorded (mirrors how
     `posts.last_error` already works for image failures)
3. Once `ready`, the post is indistinguishable from any other — shows in the client
   review link, gets approved, publishes on schedule via the existing
   `publish-scheduled` cron.

### Decided against

- **Fully synchronous generation inside the "Generate Marketing Plan" request** — ruled
  out by the 12-minute poll ceiling vs. Vercel's function timeout.
- **kie.ai webhooks instead of polling** — considered, but decided to go with the
  cron/poll pattern since it's already proven in this codebase
  (`publish-scheduled` cron) and doesn't add a dependency on kie.ai's webhook support.

## Net effect

Clicking "Generate Marketing Plan" for any car-dealer workspace now produces, without
further manual steps: 14 fixed-pillar posts, 2 rotation-seat posts (finance/comparison/
seasonal-local, whichever weren't used recently), and 3 videos with concepts that
haven't repeated in recent months — rendering in the background over roughly 30–45
minutes. No script needs to be run by hand, and no one needs to remember what ran last
month.
